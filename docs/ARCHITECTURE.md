# Как работает RAG в Astana Walk AI (высокоуровнево)

**Идея:** языковая модель (или шаблон) НЕ придумывает места. Сначала система *извлекает* (Retrieval) реальные записи из базы POI,
затем *генерирует* (Generation) объяснение только по найденным данным, затем *проверяет* результат.

```
Запрос → 1 Разбор → 2 Локация → 3 Гео-фильтр → 4 Ограничения → 5 Текстовый поиск → 6 Ранжирование
       → 7 Время в пути → 8 Мини-маршрут → 9 Объяснение (шаблон / LLM) → 10 Проверка → Ответ с источниками
```

1. **Разбор** (`query_parser.py`): язык (ru/en/kk-частично; иероглифы и т.п. — «не поддерживается»), интересы → категории с весами, время («1–2 часа», «два часа»), группа, ребёнок, коляска, «до вылета».
2. **Локация:** ориентир из текста («возле EXPO») > точка из интерфейса. Координаты проверяются и должны лежать в Астане. Нигде не сохраняются.
3. **Гео-фильтр:** радиус = половина времени × скорость ходьбы (80 м/мин) / 1.3, от 600 до 5000 м. Расстояние — формула гаверсинуса.
4. **Ограничения:** закрытые по часам OSM места исключаются; «бесплатно» — по категории/тегу `fee=no` (эвристика); для коляски исключаются `wheelchair=no`.
5. **Текстовый поиск** (`retrieval.py`): TF-IDF по словам и 3-граммам символов в документе места (названия на ru/kk/en, категория, кухня, описание, адрес). Простой, бесплатный, работает офлайн и устойчив к падежам.
6. **Ранжирование:** `0.40·категория + 0.30·текст + 0.20·близость + 0.10·полнота данных` + бонусы/штрафы (Wi-Fi для работы, доступность, ночное время и неизвестные часы, группа).
7. **Время:** пешком = расстояние/80 м/мин (оценка: прямая × 1.3, либо реальный маршрут OSRM, при сбое — откат на оценку); визит — типичное время по категории. Место должно уложиться в доступное время.
8. **Мини-маршрут** (`route_planner.py`): до 3 мест, жадный выбор с учётом оценки, расстояния и разнообразия категорий; сумма (ходьба + визиты) ≤ бюджета.
9. **Объяснение:** по умолчанию шаблоны из фактов; опционально Gemini получает ТОЛЬКО найденные места и запрос (без координат).
10. **Проверка:** (а) место существует в базе, название и координаты совпадают; (б) время согласуется с расстоянием; (в) текст LLM отбрасывается, если содержит числа вне данных, утверждения о розетках, событиях или «открыто» без подтверждения.

## Происхождение фактов (показывается в интерфейсе)
Метки в интерфейсе: OSM (из базы POI) · расчёт (вычислено приложением) · идея (шаблон, не факт) · ИИ (текст модели, проверен) · нет данных (неизвестно).

## Почему не векторные эмбеддинги
Sentence-Transformers/FAISS тянут PyTorch (гигабайты, долгая установка на Windows) и скачивание модели. На нашем объёме (тысячи мест) и при жёстком гео-фильтре
TF-IDF + категорийные правила дают сопоставимую релевантность при нулевой стоимости и полной объяснимости. Это сознательный компромисс; эмбеддинги — шаг развития (см. презентацию).
