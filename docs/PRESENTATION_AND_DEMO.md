# Презентация (5–7 мин), сценарий демо, видео и ответы жюри — команда Unsurprised

## Слайды (7 штук, ≈6 минут)
1. **Проблема (40 с).** Человек в Астане не знает, куда пойти «прямо сейчас»: карты показывают всё подряд, чаты выдумывают места. Нужны релевантные, проверяемые подсказки с учётом времени и локации.
2. **Решение (40 с).** Astana Walk AI: запрос на естественном языке → 1–3 реальных места или мини-маршрут → «почему», время, «что делать», источник каждого факта.
3. **Как это работает — RAG (60 с).** Схема из `docs/ARCHITECTURE.md`: гео-фильтр → ограничения → поиск → ранжирование → расчёт времени → объяснение → проверка. Подчеркнуть: ИИ не придумывает места.
4. **Живое демо (120 с).** Сценарии ниже.
5. **Тесты и честность (50 с).** Число автотестов (`pytest`), `docs/TEST_RESULTS.md`, граничные случаи (пустая база, неверные координаты, недоступный OSRM, чужой язык, неизвестные часы). Метки источников.
6. **Этика и приватность (30 с).** Координаты не сохраняются; LLM не получает координат; «неизвестно» вместо выдумки.
7. **Ограничения и развитие (40 с).** Ограничения OSM, нет данных реального времени. План: эмбеддинги, события (афиши), реальные маршруты по умолчанию, казахский, голос/Telegram-бот, партнёрские данные НИЦ Smart City.
*(В цифры на слайдах подставляйте только то, что показал ваш собственный прогон: число POI, число тестов, результаты `run_scenarios.py`.)*

## Сценарий демо (2 минуты)
1. Показать боковую панель и фразу про приватность (10 с).
2. **EXPO:** кнопка-пример №1. Показать карточки: расстояние, время, «почему» с метками, ссылку на OSM (30 с).
3. **Работа:** пример №2. Показать, что система пишет «Розетки: данных нет — не подтверждено» вместо обещания (25 с).
4. **Группа:** пример №3. Показать мини-маршрут и итоговое время (30 с).
5. **Турист за 2 часа:** запрос «два часа до вылета» — система осторожна, закладывает запас на аэропорт (20 с).
6. Включить «Только бесплатное» или «коляска» и показать, как меняется выдача (15 с).

## План видео (YouTube, ≤ 5 мин)
Запись экрана (Win+G или OBS) + голос. 0:00 название и команда · 0:20 проблема · 0:50 демо 3 сценариев · 3:30 тесты (`pytest`, `TEST_RESULTS.md`) · 4:15 ограничения и приватность · 4:45 итог.
Перед записью: запустить `run_scenarios.py`, проверить, что все автопроверки [OK], выбрать запросы, где выдача выглядит разумно **на ваших реальных данных**. Загрузить на YouTube как «доступ по ссылке», вставить ссылку в форму сдачи.

## Возможные вопросы жюри и короткие ответы
1. **Где здесь RAG?** — Сначала извлекаем реальные места (гео-фильтр + TF-IDF), потом объясняем только по найденному и проверяем результат; без найденных данных ответа нет.
2. **Откуда данные и как они собираются?** — OpenStreetMap через Overpass API; `collect_poi.py` автоматизирован: группы запросов, повторы, кэш, дедупликация; повторный запуск обновляет базу.
3. **Почему не эмбеддинги/LLM по умолчанию?** — Бесплатно, офлайн, объяснимо; при гео-фильтре и малой базе лексического поиска достаточно. LLM подключается опционально и проходит верификацию.
4. **Как вы защищаетесь от галлюцинаций?** — Места берутся только из базы; шаблонные объяснения строятся из фактов; текст LLM отбрасывается при числах вне данных или утверждениях о розетках/событиях/открытости.
5. **Как считаете расстояние и время?** — Гаверсинус; по умолчанию оценка ×1.3 к прямой, помечена как оценка; опционально OSRM; время = путь / 80 м/мин + типичное время визита.
6. **Что если нет часов работы?** — Пишем «неизвестно», слегка снижаем рейтинг (сильнее ночью), не утверждаем «открыто».
7. **Как с приватностью?** — Координаты не хранятся и не логируются; ручной ввод; LLM координат не получает.
8. **Что с событиями?** — Данных о событиях нет, поэтому система прямо об этом сообщает. Интеграция афиш — план развития.
9. **Как проверяли качество?** — Автотесты ядра, прогон 6 сценариев и 8 граничных случаев на реальных данных с автопроверками; результаты в `TEST_RESULTS.md`.
10. **Главные ограничения?** — Полнота OSM (мало описаний/часов), нет real-time, расстояния без OSRM приблизительные.
11. **Как масштабировать?** — Добавить источники (2GIS/муниципальные данные по лицензии), эмбеддинги, кэш маршрутов, мобильный клиент/бот.
12. **Какая бизнес-идея?** — Городской туристический сервис/бот для НИЦ Smart City и партнёров; монетизация через B2B (отели, музеи, события) при сохранении честной маркировки рекомендаций.
